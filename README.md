# GM Recipes Reborn

[![Netlify Status](https://api.netlify.com/api/v1/badges/50b64b5a-e097-463a-a8e6-176333f8959d/deploy-status)](https://app.netlify.com/sites/gm-recipes-reborn/deploys)

- [Netlify preview](https://gm-recipes-reborn.netlify.app/)

## About

GM Recipes Reborn is a small React app that lets you browse and filter recipes for GM
multicookers ("Ollas GM"). The recipe data is scraped from the
[ollasgm.com](https://www.ollasgm.com/blog) blog and bundled into the app, so you can
filter recipes by difficulty and search them by text without paging through the
original site.

**Stack:** React 19, Webpack 5, Sass. No TypeScript, no backend — it's a static app.

## Getting started

### Requirements

- Node.js 20 (see [`.nvmrc`](.nvmrc); if you use [nvm](https://github.com/nvm-sh/nvm),
  run `nvm use`)
- [Yarn](https://yarnpkg.com/) (the repo uses `yarn.lock`, not npm)

### Install

```bash
yarn install
```

### Run in development

```bash
yarn start
```

This starts `webpack-dev-server` using [`build/webpack.config.dev.js`](build/webpack.config.dev.js)
with hot module replacement enabled. It serves on webpack-dev-server's default port
(`http://localhost:8080` unless overridden).

### Build for production

```bash
yarn build
```

Runs webpack with [`build/webpack.config.prod.js`](build/webpack.config.prod.js) and
outputs the static site to `dist/`.

### Formatting

```bash
yarn format         # apply Prettier formatting
yarn format:check   # check formatting without writing files
```

## Recipes data & scraping

`data/recipes.json` is generated by a standalone Node script (not part of the webpack
build) that scrapes [ollasgm.com/blog](https://www.ollasgm.com/blog):

- [`utils/node-scraper/script.js`](utils/node-scraper/script.js) orchestrates the
  process: it fetches the total number of pages, then for each page fetches the
  recipe list and the details of every individual recipe.
- [`utils/node-scraper/modules/total-pages.js`](utils/node-scraper/modules/total-pages.js)
  reads the pagination info from the blog listing.
- [`utils/node-scraper/modules/recipes-in-page.js`](utils/node-scraper/modules/recipes-in-page.js)
  extracts the title and link of every recipe on a listing page.
- [`utils/node-scraper/modules/recipe-data.js`](utils/node-scraper/modules/recipe-data.js)
  visits each recipe page and extracts difficulty, servings, time and image.

It's plain HTTP scraping with [`axios`](https://www.npmjs.com/package/axios) and
[`cheerio`](https://www.npmjs.com/package/cheerio) — no headless browser is needed,
since the site doesn't require JavaScript to render recipe content.

### Running it locally

```bash
yarn scraper
```

This overwrites `data/recipes.json` with a freshly scraped, pretty-printed JSON array.
It takes several minutes, since it walks every page of the blog and fetches every
recipe individually.

### Automated scraping (GitHub Actions)

The [`Scrape recipes`](.github/workflows/scrape-recipes.yml) workflow runs the same
`yarn scraper` script in CI and, if the resulting `data/recipes.json` differs from what's
committed, pushes the update straight to the repository. Since the app imports
`data/recipes.json` as a static module, that push triggers a new Netlify build with the
updated recipes — no manual build step needed.

The workflow is **manually triggered only** (`workflow_dispatch`, no schedule): run it
from the Actions tab on GitHub, or with `gh workflow run scrape-recipes.yml`, whenever
you want to refresh the data.

### Known limitations

- **No rate limiting or retries.** Requests to ollasgm.com aren't throttled, don't set a
  custom `User-Agent`, and aren't retried on failure — a busy or blocking origin server
  can cause partial or failed scrapes.
- **Partial failures are silent.** If a recipe's detail page fails to parse, that recipe
  is kept in the output with missing fields; the app filters out recipes without both an
  `image` and a `difficulty` at render time ([`src/app.jsx`](src/app.jsx)).
- **No incremental mode.** Every run re-scrapes the entire blog from scratch; there's no
  caching or diffing against the previous run.
- **Empty-result guard.** If the scrape produces zero recipes (e.g. the origin site
  blocked or failed the very first request), the script aborts without touching
  `data/recipes.json`, so a failed run can never wipe out the existing data.

## Deployment (Netlify)

The app is deployed on Netlify from the `master` branch. Build settings are versioned in
[`netlify.toml`](netlify.toml):

```toml
[build]
  command = "yarn build"
  publish = "dist"
```

Every push to `master` — including the automated commits from the scraping workflow
above — triggers a new Netlify build and deploy.
